# ADR-0013 — epubcheck distribution: locator-first with documented install paths; bundle decision deferred to the installer

**Status:** Accepted (post-P5 maintenance slice, 2026-11-11; resolves OQ-16)
**Context:** The P5 exit gate made epubcheck an external blocking gate (ADR-0011): a retail package is clean only when the real epubcheck 5.2.1 reports zero errors. OQ-16 asked what the distribution story for writers is — the tool is not bundled with the app, and a writer machine without it can only get an honest UNVERIFIED (not clean) ship report. The app already resolves the tool through `desktopbridge/EpubCheckLocator`: `EPUBCHECK_JAR` env → `EPUBCHECK_HOME` env → app-dir/`.build-extras` → `~/.authr/epubcheck`.
**Decision:** (1) Keep the locator-first model as the contract; do not embed a Java EPUB validator in the app. (2) Document three supported install paths in `docs/config-and-env.md`: the per-user install into `~/.authr/epubcheck` (the default a writer sees), the env-var overrides for CI/gate machines, and `scripts/p5_fetch_toolchain.sh` as the reproducible fetch for this repo's own gates. (3) **Bundling the ~10 MB dist in the installer is the target story, deferred to installer packaging time** (same slice that bundles the print TTFs, D-16): it turns on with the Publishing workbench UI (D-15), because until writers can package from the app, every clean package is produced on a gate/CI machine where the env-var path already works. (4) The UNVERIFIED-not-clean verdict remains the honest failure mode when the tool is absent — no silent pass, no auto-download at runtime (a network fetch inside a "deterministic local gate" would make the verdict depend on the network, which the locator model deliberately avoids).
**Alternatives considered:** runtime first-run downloader (rejected — a gate that needs the network to pass is a gate that can fail opaquely; the program's discipline keeps gates local); vendoring the dist into the git repo permanently (rejected — 34 MB of jars in git, restorable any time via the fetch script; the repo keeps only the evidence, not the toolchain); waiting for bundling before any decision (rejected — leaves writers with an undocumented tool).
**Consequences:** `~/.authr/epubcheck` becomes a documented, supported location (config-and-env lists it). OQ-16 closes with the deferral explicitly owned by the installer/D-15 slice. The gate evidence trees stay reproducible: the fetch script + env vars.
**Do not change unless:** the installer packaging starts (then bundle and flip the locator's last-resort to the bundled path first).
**Evidence:** `desktopbridge/EpubCheckLocator.kt` (resolution order, FACT), `scripts/p5_fetch_toolchain.sh` (reproducible fetch), `docs/config-and-env.md` (EPUBCHECK_* rows), `RetailPackagerTest` (UNVERIFIED ≠ clean, real-tool integration), `docs/open-questions.md` OQ-16 (closed 2026-11-11).
