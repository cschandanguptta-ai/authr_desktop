# Tech Debt

Shortcuts, fragile code, scaling limits — each with file refs and a blast-radius note. Priority: D-01 first.

| ID | Item | Where | Impact | Suggested direction |
| --- | --- | --- | --- | --- |
| **D-01** | **Autonomous worker chain never executes on desktop**: the WorkManager shim's `runSingle` requires a factory registered via `DesktopWorkManager.registerWorker(...)`, and zero call sites register any worker. Chains enqueued from `StudioViewModel` (≈ lines 4179–4183, 4259–4263, 4349–4353) and `StoryEditorViewModel` (≈ line 82) log `"No factory for …"` and stop; DAO-backed worker constructors (`CompilationWorker(bookDao, …, chekhovGunDao, serialArcDao, questionDao)`) get their DAOs only via factories that don't exist. | `androidx/work/WorkManager.kt` (`runSingle` ≈ line 480), `worker/*.kt` | The Autonomous Studio's background pipeline is inert on desktop; engine gates are proven by tests instead. This is the single largest functional gap of the port. | Register factories (a Koin-free registry in `Main.kt` is enough), wire `AppDatabase` into worker construction, then move the compile-path gate tests up to integration level. |
| **D-02** | **`fallbackToDestructiveMigration(true)`** in `AppDatabase.getDatabase` — a missed migration silently wipes user data instead of failing loudly. | `data/local/AppDatabase.kt` ≈ line 178 | Data-loss risk on schema drift. | Remove the fallback; ship explicit migrations only. |
| **D-03** | **Silent crypto downgrade**: `getSecurePrefs` catches keystore failures and returns a PLAIN `SharedPreferences` (`secure_studio_settings_fallback`) — API keys can persist unencrypted with no user signal. | `data/api/LlmOrchestrator.kt` ≈ lines 30–46 | Confidentiality risk on devices with broken keystores. | Distinguish fallback storage (in-memory only, or fail fast + surface in Settings). |
| **D-04** | **God-classes**: `StudioViewModel` (5,496 lines) and `StoryScreen.kt` (4,446 lines) mix library, wizard, pipeline control, TTS, logs, and import/export. | `ui/viewmodel/StudioViewModel.kt`, `ui/screens/StoryScreen.kt` | High merge-conflict surface; any touch recompiles the world; hard to test UI-layer logic. | Split per workspace (Library/Wizard/Pipeline/Logs) following the `WriterStudioViewModel`/`SerialDashboardViewModel` pattern. |
| **D-05** | **Hardcoded ISBN + auto-marketing** in `CompilationWorker` (`ISBN: 978-6648-507-48-5`, marketing/cover LLM calls inside compile). | `worker/CompilationWorker.kt` ≈ lines 113–147 | Wrong metadata in every compiled manuscript; compile depends on LLM availability. | Move to book metadata fields (P5 metadata workbench, plan §12). |
| **D-06** | **Test fixtures duplicate fake DAOs** across test classes (Story/Book/Chapter/Lorebook/Question fakes copy-pasted in `ChekhovLedgerTest`, `SerialDashboardTest`, others). | `desktop/src/test/kotlin/com/example/*Test.kt` | Divergent fake behavior as DAOs evolve. | Extract a shared `fakes/` package when a third phase needs the same fakes. |
| **D-07** | **No CI**: no pipeline config in the repo; the suite (130 tests) runs only where a developer runs it. | repo root (absence) | Regressions can land unnoticed. | Any CI runner with JDK 21 + `./gradlew :desktop:test` (cache Gradle deps to dodge Central 429 bursts). |
| **D-08** | **Scaling limits of regex validators**: cue-regex scanning is O(text) per check and the echo detector is O(n·window); chapters far beyond the 1,000–2,000-word envelope (e.g. 20k words) will feel slow in the annotator path. | `engine/LiveAstAnnotator.kt` (continuityFlags), `ClicheCleaner.scan` | Latency only, no correctness risk. | Cap or window the echo scan; memoize per text-hash. |
| **D-09** | **Dashboard export picker truncates profiles** (`SerialExportProfiles.PROFILES.take(4)` in `SerialDashboardScreen.kt`) — six profiles exist, four are reachable in the UI row. | `ui/screens/SerialDashboardScreen.kt` | Writers can't select Dreame/Webnovel/Tapas from the row. | Replace with a dropdown; batch export already supports all ids. |
| **D-10** | **`StudioViewModel` logs** (`fetchLogcat`) read process logs on desktop via the shim — fidelity of "developer logs" varies by platform. | `ui/viewmodel/StudioViewModel.kt` ≈ line 282 | Diagnostic noise only. | Route through the agent-chat store instead. |
| **D-11** | **Gradle sandbox tuning baked into `gradle.properties`** (`org.gradle.java.home=/tmp/my-project/tools/jdk`, mavenLocal-first in `settings.gradle.kts`) — workstations with different layouts must edit these before building. | `gradle.properties`, `settings.gradle.kts` | Build friction outside the original sandbox. | Make the JDK path overridable (`-Dorg.gradle.java.home=…` on the CLI already wins; document it). |
| **D-12** | **Serial validation runs twice per compile** (WriterStudioViewModel refresh + CompilationWorker suite) with no memoization — negligible for now, but the golden-corpus probe shows ~140 checks per run. | `SerialValidatorSuite.run` call sites | CPU seconds on large serials. | Cache by (bookId, max textHash) like the AST does. |

## Deliberate non-goals (not debt)

- No platform APIs for serial publishing (ADR-0009).
- No LLM-as-judge assertions (ADR-0004).
- No destructive DB migrations (ADR-0002, invariants #3).
- Polls never influence the engine (plan §6.10; invariant #12).
